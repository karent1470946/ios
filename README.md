前七篇是同一句话的七个部分：**输入到达的方式（网页、内容字节、接口调用、有线插入、卷挂载、线上报文）决定谁来解析它，解析所在的层决定缺陷的后果起点，而后果起点决定这件事是"厂商修"还是"你能关"。** 其中只有 #123 是远程触发的：它不需要你碰任何东西，也不需要介质靠近，所以它的"关不掉"权重比其余各篇更高一档。

第八篇往下再切一层，问的不是"谁来解析"，而是"**解析出来的东西由谁能解密**"。#118 讲文件里的字节、#122 讲卷结构的字节、#123 讲线上的字节，而 #124 讲保护这些字节的那把钥匙：算法没有被攻破，数据照样可读——因为缺陷藏在用法（只加密不认证、nonce 重用、随机源、该验没验）与生命周期（密钥落在哪个容器、派生强度、撤销与销毁）里，而不是藏在数学里。这一篇也是八篇里唯一一类**个人杠杆真的生效**的：多数组件缺陷只能等更新，而密钥归属由用户与组织自己决定。它同样是唯一**向过去生效**的风险——今天泄露的钥匙打开昨天的数据，所以其余各篇的时间窗口模型在这里要反过来用。
