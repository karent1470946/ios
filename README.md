前七篇是同一句话的七个部分：**输入到达的方式（网页、内容字节、接口调用、有线插入、卷挂载、线上报文）决定谁来解析它，解析所在的层决定缺陷的后果起点，而后果起点决定这件事是"厂商修"还是"你能关"。** 其中只有 #123 是远程触发的：它不需要你碰任何东西，也不需要介质靠近，所以它的"关不掉"权重比其余各篇更高一档。

第八篇往下再切一层，问的不是"谁来解析"，而是"**解析出来的东西由谁能解密**"。#118 讲文件里的字节、#122 讲卷结构的字节、#123 讲线上的字节，而 #124 讲保护这些字节的那把钥匙：算法没有被攻破，数据照样可读——因为缺陷藏在用法（只加密不认证、nonce 重用、随机源、该验没验）与生命周期（密钥落在哪个容器、派生强度、撤销与销毁）里，而不是藏在数学里。这一篇也是前八篇里唯一一类**个人杠杆真的生效**的：多数组件缺陷只能等更新，而密钥归属由用户与组织自己决定。它同样是唯一**向过去生效**的风险——今天泄露的钥匙打开昨天的数据，所以其余各篇的时间窗口模型在这里要反过来用。

第九篇再换一根轴：前八篇问的都是"一段字节进来，谁来解析它"，#125 问的是"设备知道自己在哪里、在做什么，这件事是从哪些层攒起来的"。定位与传感器没有"恶意文件"那样的入口，它的缺陷不在解析器里，而在**契约**里：来源即位置（信号本身没有身份）、授权即语义（关掉一个 App 的定位权限，运动与环境传感器仍按另一套口径被使用）、新鲜度假设、名字与对象分离、融合不可归因（所以逐项撤销根本不成立）、指示器即完整可见、失败即信息（拒绝授权本身被当成一次回答）。这也是前九篇里**可观测性最弱**的一篇：你能核对"自己给了多少"，核对不了"上层把哪些来源融合成了什么结论"；而其中一部分定位发生在服务端，设备上不留下任何可供审计的痕迹。个人杠杆在这里是部分的：服务级开关真的有效，融合层与原始传感器关不掉。它还给后果表添了一格前八篇没有的：**判定污染**——被污染的定位不只泄露你的行踪，还会写进考勤、门禁与理赔这些第三方记录里，而那里的损失不由设备厂商赔。

第十篇把方向倒过来：前九篇（除了 #124）处理的都是**输入**——外部字节或外部信号到达时，系统替你解析了什么、测量了什么；#126 处理的是**输出**——外部信号到达时，系统允许它**替你按下什么**。这一族的入口不是文件也不是报文，而是一组看起来无害的无障碍开关，以及三条没有身份概念的触发通路：声音（语音控制的自定义命令是一段可被**任何到达音频**触发的预置动作串，判定项里没有"说话的是谁"）、动作（摄像头与后置麦克风可以被当成开关输入）、连接（配对记录代表"这台设备被信任过"，不代表"此刻操作的是这个人"）。它的四个结构性结论是：**一次授予、全域生效**（界面措辞是"打开一个功能"，实际给的是一项覆盖任意前台内容的读取与操作能力，包括其他 App 显示的验证码）；**恢复即同意**（迁移与备份恢复把开关与已信任外设带回设备，其间没有任何一次重新征询——与 #107 的撤销不对称同族，但方向相反，是没打开过却已经是开的）；**锁屏不是输入隔离状态**（锁屏保护的是数据访问，不保证输入通路不可达）；以及本篇最重要的那条——**这是全系列第一个不提权的接管**：所有动作都发生在用户自己的会话、自己的权限、真实的界面里，所以服务端记录与本人操作不可区分，#91 的 C3 那一行"攻击者获得更高控制权"在这里要加注"权限等级未变"，归因只能靠形状与时间，不能靠记录本身。它还纠正一个从 Android 搬过来的直觉：iOS 上**没有第三方 App 可注册为辅助功能提供方**，所以"无障碍服务被监控软件滥用"这条路径在 iOS 上没有等价物——本族的风险面在系统功能 + 外部输入源 + 配置通道三者之间，"先查有没有可疑 App"这个第一反应在这里基本无效。可观测性与 #125 同档：开关当前态可见，变更的时间、来源与"这次操作是否来自合成事件"不可见，因此本篇不提供"如何发现自己被外部操作"的判定式，只提供十分钟清点 + 收窄触发源 + 记录基线三件事。

第十一篇把镜头从"系统自己的功能"移到"**系统开给第三方代码的那些插槽**"。前十篇里，要么是一段外部字节被系统解析，要么是系统自带能力被外部信号触发；#127 问的是第三件事——**你装进去的那一段第三方代码，是怎么拿到系统能力的**。它的答案不在权限清单里：**能力跟着插槽走，不跟着权限清单走**。填了键盘位就能看到所有 App 的输入，填了网络过滤位就能改写所有页面的内容，填了文件提供位就代宿主去取远端字节，填了通知处理位就在消息送达前拿到附件，填了意图与自动化位就能在无人复核时执行一串动作。这条结论有一个方法论后果，也是本篇最想让人带走的一句：**只用隐私面板的口径做审计，会系统性漏掉这一整族**——键盘全访问、网络扩展、文件提供方、通知处理与意图自动化都不在"隐私与安全性"那张授权列表里，各有自己的入口，且没有一个显示为"一次授权"。所以它的三层切分落在 X1 槽位声明与匹配 / X2 上下文与数据交接 / X3 能力与生命周期上：**缺陷密度在 X2**（宿主递过来的是副本、共享容器还是一个引用，决定了扩展事后能不能"没拿到"），**长期风险在 X3**（启停开关分散在四个互不相邻的设置面板，启用没有到期时间）。两个最反常识的触发点：**T3 一个开关即全量输入可见**（"允许完全访问"不是隐私面板里的一项授权，它看到的输入来自所有 App，而不只是它自己那个），**T4 一个配置即全量流量与页面改写**（规则是提供方写的，信任是你给的，判定项里没有"哪些域名该给它看"这个粒度）。后果形状与 #126 是同族的另半边：**#126 是借系统自己的功能替你按下按钮，本篇是你请进来的另一段代码，在系统给它的沙箱里看见了你正在做的事**——同样不提权，同样全程合法，但工件落在提供方的容器里，既不在你的设备上，也不进你的备份，所以这一族的处置依然只能是降级而不是发现。正向结论也要写下来：**iOS 的扩展没有任意常驻后台**，进程由宿主按需拉起、内存受限、生命周期由系统决定（这是它与 Android 输入法/无障碍常驻的结构性差异，接 #112），因此伤害形状偏向"一次会话内的可见性 + 它带走的那一份"，而非长期监听。个人杠杆在前十一篇里最高：**插槽是你自己插进去的，能关的也确实是这些插槽**（下一篇只有在“查询与出口”那一段接近它，聚合本体那一段关不掉）；可观测性比 #125/#126 高一档但方向很特别——结构可完整枚举（十分钟列全"哪些槽位被谁占了"），行为几乎无工件（拿不到"被唤起过多少次、处理过什么、回传了什么"），所以审计口径是**列结构、不追行为**，任何声称能在设备侧查到扩展行为流水的说法都不成立。

第十二篇把时间轴往后挪：前十一根竖条问的都是某个东西**进来**的那一刻（字节、接口调用、有线插入、卷挂载、线上报文、外部信号、被唤起的第三方代码），#128 问的是**留下之后**：内容被存进一个跨 App 的可查询结构以后，谁还能把它和别的东西放在一起看到。它的名字应该叫**数据跟着索引走，不跟着沙箱走**——数据在各自 App 的沙箱里由授权模型管着，一旦进入聚合区，管着它的就只剩排序模型，**那里没有权限模型**。三层切分是 I1 抽取与写入 / I2 存储与合并 / I3 查询与外发：**缺陷密度在 I2，而 I2 恰好是唯一拆不掉的一层**（没有“关掉聚合但保留功能”这个选项），个人杠杆全部集中在 I1 与 I3，且关闭效果能用一次搜索当场验证。两个最反常识的触发点都不需要攻击者：**T4 建议即前置披露**（派生结论在解锁之前就摆到锁屏与前台，读者是同处一室的人——解锁保护的是数据访问，不保证屏幕可见性，这是 #126 那条锁屏结论在显示层的等价物），以及 **T5 查询即出口**（你以为发生在本机的一次搜索，可能伴随一次把查询词发往服务端的联想请求；#103 管“你连到哪”，这一篇管“你问了什么”）。它最硬的两条结论是 **M3 沙箱不外推**（某 App 的数据受该 App 的口径约束，这一条不因它被系统索引而转移）与 **M4 合并即新数据**（日程 + 位置合成作息、联系人 + 频率合成关系强度——合成出来的那一类你从未单独拥有过，也没单独交出过，这是 #95 追踪后果的机制层）。三条老规律在这里第三次成立，说明它们是结构性而不是偶发的：**融合不可归因**（#125 的 M5，逐项撤销在索引层同样不成立）、**恢复即重新聚合**（#126 的“恢复即同意”的聚合版：换机与备份把结构和已删除内容的副本一起带回来）、**关闭只对未来生效**（#107 的撤销不对称，第一次出现在设备内部而不是出口上）。方法论上它给出 #66 隐私面板口径的**第二个系统性漏检**：第一次是 #127 的插槽（能力不显示为授权），这一次是聚合——**没有任何一次同意对应“被并入跨 App 可查询结构”这件事**，所以需要一张来源清单而不是权限清单的补充项。分界也要说死：**#118 处理“字节到达即解析”，这一篇处理“内容到达即聚合”；#127 讲插槽给能力，这一篇讲供数给可见性**，两者是同一条链的前后两半。可观测性处在中间偏上：来源能在十几分钟内完整枚举，但写入时间、查询流水、副本清除与合成规则四项不可核验，所以本篇只承诺“下一次搜索不再返回它”，不承诺“能证明已经清空”——任何声称能查到索引读写流水的说法都不成立。

第十三篇把整族的坐标轴换掉：前十二根竖条里，无论是解析器、接口、插槽、聚合层还是能力授予，缺陷都发生在**设备内部**——某段字节被解析、某个调用被授予、某份内容被合并。#129 的缺陷发生在**另一个人的基础设施里**：凭证由运营商签发、由运营商保管、由运营商的客服流程决定是否重新签发给谁。所以它的名字应该叫**身份跟着签约关系走，不跟着设备走**，而本篇最重要的一句话是：**攻击者不需要接触你的设备，也不需要攻破任何软件，就能推进一次认证**。三层切分是 S1 订阅与凭证 / S2 通道与路由 / S3 依赖与替代：**缺陷密度在 S3**（那是别人的设计选择——多数服务把"号码可达"放在认证因子清单优先级最高的一格），**长期风险在 S1**（归属与撤销都在签发方，用户只能申请、不能撤销），**S2 是设备唯一还能观察到一点的那一段**（路由不是认证：分派规则决定内容落在哪块屏幕，不决定"这是不是给我的"）。两个最反常识的触发点：**T3 重新签发不需要旧凭证在场**——全系列第一个"不需要持有、只需要通过身份核对"的入口，也是唯一一类攻击者拿的是文档而不是载荷；**T5 号码回收即身份交接**——二次放号不是缺陷，是回收流程的默认结果，因此没有任何一次事件会通知你。它给系列的三条既有规律各加一个形态：**#107 的撤销不对称在这里翻转**（不是"你关掉的只对未来生效"，而是"**你什么都没关，别人能把它打开**"）；**#126/#127 的不提权接管有了第三种形状**（#126 借系统功能、#127 借你请进来的代码、本篇借一个别人认得出你的标识符，服务端记录显示为本人操作，归因不能靠记录本身）；**#92 的"不可逆子集活在账户与政策层"**（通道可夺回，但已完成的转账与账户恢复不可逆）。七种契约违背里有五条（号码即身份、撤销单侧、重签发无到期、回收即清空、失败即信息）**不是软件缺陷而是流程与语义的默认设定，因此没有一行代码可以改**——这是本篇与整个组件族最大的方法论差异。由此产生两个诚实结论：其一，**端侧可观测性是全系列最弱的一档**，这一族的变更根本不在设备上留下事件，所以本篇不提供"如何发现自己被转移"的判定式（在本族这种判定式不存在），只给"列关系 + 换因子 + 外部核对"三件事；其二，处置重心不是关闭而是**降级与替换**——把"可达性"从认证因子清单里请出去，是个人在这条链上唯一确实生效的动作，也因此它是全系列少数几篇**个人杠杆生效点完全不在系统开关上**的。方法论上它还给出第三个漏检口径：只用隐私面板、扩展槽位清单或索引来源清单做审计，会**系统性漏掉这一整族**，因为它压根不是设备里的一项配置，而是设备外的一段关系——所以需要一张**关系清单**，而不是又一个开关清单。

第十四篇把方向换了最后一次：前十三根竖条处理的对象依次是进来的字节（#118 文件格式、#122 卷结构、#123 线上报文）、进来的调用（#119 用户态接口、#127 第三方插槽）、进来的设备与信号（#121 有线配件、#125 定位与传感器、#129 号码与订阅）、进来的操作请求（#126 辅助功能与外设触发），以及留下之后被合在一起的内容（#128 本地索引与聚合）。#130 处理最后一类方向：**内容被画到屏幕上之后**。它的名字叫**像素跟着合成器走，不跟着沙箱走**——授权模型管的是"能不能采集"，显示层管的是"已经在屏幕上"，而显示层里没有权限模型，只有"这块画层能不能被合成出来"。三层切分是 D1 渲染与合成 / D2 捕获与再导出 / D3 归属与留存：**缺陷密度在 D2**（通路多、粒度粗、授权的单位是会话而范围的单位是屏幕，一次启动即覆盖全域），**长期风险在 D3**（捕获出来的那一份落在谁的相册、谁的服务器、哪台并不属于你的设备上，你的撤销动作够不到它，这一层是本篇唯一没有任何设备侧杠杆的地方），**D1 是这套体系唯一还能表达意图的位置，而它的表达方式恰好是最弱的一种**——机密性由内容自己请求、粒度落在画层而不是信息，所以同一句话在两个 App 里命运不同。两个最反常识的触发点：**T4 镜像即交接**（画面一旦投给会议服务器、电视、车机或协作中继，约束它的是那一端的策略，你在 iOS 里做的所有显示相关开关在那一端一律失效），以及 **T5 指示器只说"有捕获"，不说谁在看、看到什么、去了哪**（录制与共享的可见提示是真实的，但把指示器读成"我被告知了全部"是本族最常见的误判）。与 #126 的分界必须写清楚，因为两篇都涉及"别人看到了你的界面"：**#126 读的是无障碍树**（控件、标签与语义，代价是能读也能操作，入口是一组无障碍开关），**本篇读的是像素**（不需要任何 App 开启无障碍能力，也不需要被读取的那个 App 配合，入口是显示通路本身）；两者共同点是不提权、不越狱、全程发生在用户自己的会话与真实界面里，因此记录与本人操作不可区分——在 #126、#127、#129 之后，这是**第四种不提权的伤害形状：被读的不是数据，是画面**。**M2 沙箱不外推**是同一条律的第二次成立：#128 说某 App 的数据不因被系统索引而转移口径，本篇说某 App 的内容不因被渲染到屏幕上就多出一层保护。方法论上它给出 #66/#88 隐私面板口径的第三个系统性漏检（前两次是 #127 的槽位与 #128 的聚合；#129 那一段压根不在设备里，属于另一个口径）：**没有任何一项授权对应"内容正在被显示"这件事**，因为显示不是一个需要申请的能力，而是设备被造出来的目的，所以需要一张通路清单加一张在场者清单。正向结论也要写下来：**iOS 上任何第三方捕获都必须有一次用户可见、可撤销的启动，并有系统级指示**——这是它与 Android 屏幕捕获生态的结构性差异（接 #112），因此伤害形状偏向"**一次显示即一次披露**"而非长期被录。可观测性中间偏弱、与 #126 同档：捕获会话与投屏目的地当场可见，但被捕获的图层构成、平台留存多久、接收端有没有再投一次、谁截了你发出去的内容四项不可核验，且 **iOS 不提供跨 App 或跨设备的截屏审计**，所以本篇同样不提供"如何发现自己被捕获"的判定式，只提供列通路、收范围、外部核对三件事。它还给后果表添一格新的位置——**读者在设备之外**：一个坐在你对面的人或另一台机器上的一段录制，都不与你的设备发生任何关系，因此"检查设备就能排除"的判断在这一族不成立；#125 首创的**判定污染**也在这里第二次成立（伪造的界面一旦进入会议录制与投屏画面，就作为"当时确实这样显示过"长期留在第三方记录里，而那里赔钱的不是设备厂商）。

第十五篇把方向换了最后一次，而且换的是最反直觉的一次：前十四根竖条问的都是**系统怎么处理数据**——字节怎么被解析（#118/#122/#123）、调用怎么被受理（#119/#127）、设备与信号怎么被读入（#121/#125/#129）、操作请求怎么被授予（#126）、留下的内容怎么被合在一起（#128）、画出来的像素怎么被再导出（#130）。#131 问的是**系统怎么处理"身份的可读形式"**：一个对象在你眼前呈现成什么样子是谁决定的，而你据此做出的判断最后落在了哪个对象上。它的名字叫**判定跟着渲染结果走，不跟着真实对象走**——界面上的名字不是身份，身份由注册域、完整地址、签名标识符、发件地址与证书决定，而这两层之间**没有任何一处做一致性核验**：呈现层只负责看起来像，执行层只负责是哪个对象，承担后果的是人。三层切分是 N1 对象 / N2 呈现 / N3 判定与落点：**N1 是唯一有客观真相、可枚举、可撤销的一层，但它通常不直接显示给你**；**缺陷密度在 N2**，因为那里的供稿方与担责方不是同一个人——链接卡片的标题与摘要由被链接一方撰稿、显示名与图标由对象发布者自填、地址只显示被裁断的那一段、形近与码位组合让"看上去一样"不等于"字节一样"、区域与字号还会改变截断位置与阅读顺序；**长期风险在 N3**，因为授权按 N1 存储、判断按 N2 做出、事后管理又按 N2 的记忆去查找，所以"我当时明明看到是官方名字"推不出"我授权的是官方对象"，而撤销时常常找不到自己当初开过的那一项。两个最反常识的触发点：**T1 预览即对方撰稿**——在你"只是看了一眼"的那一秒里，对方的文案已经决定了问题是怎么问的，而这次抓取本身还先向对方证明了一次在场；**T5 重名没有唯一属主**——商店侧确实有名称约束，但主屏幕 Web 链接、快捷指令、配置文件、企业签名 App、配件与网络名仍可与他人重名，冲突按注册与优先级解决，而那个优先级不显示给你。与 #130 的分界是本系列最容易混淆的一对，两篇都以屏幕为场地但方向相反：**#130 是出口（内容画成像素之后会离开到哪去），本篇是入口的判读（内容到达时是怎么被你认出来的）**；与 #97 的分界也要写死：**那边给骗局的路径与拦截动作，本篇给冒充得以成立的技术条件**——你用来警惕的那个信息本身是谁写的；与 #87 的分界则是机器读屏幕 vs 人读屏幕，两半合起来才是同一块界面上的双向误读。方法论上它给出 #66 隐私面板口径的**第四个系统性漏检**（前三次是 #127 的槽位、#128 的聚合、#130 的显示）：**没有任何一项授权对应"这个名字被显示成这样"**，因为呈现不是被申请的能力而是界面被造出来的目的，所以需要一张**对象—显示对照清单**，而不是又一个开关清单。后果上它有两个独占位置：其一，**C6 判定污染的正主**——#125 首创、#130 第二次成立，而本篇给出它的发生地，伪造的界面文本进入工单、客服会话与审批流水之后就长期作为"用户当时看到的确实是官方界面"存在，这一格赔钱的不是设备厂商；其二，**第五种不提权的伤害形状：借你自己的手**——#126 借系统功能、#127 借你请进来的代码、#129 在别人的系统里你就是本人、#130 被读走的不是数据是画面，本篇是**用户以本人的真实手势完成了攻击者需要的那一步**，因此 #78/#116 那套归因与时间窗模型在这里到达极限：没有第二种形态可以区分，因为这就是第一种。可观测性的诚实定位是**中间档且时间方向严重不对称**：对象可以当场展开（完整地址、真实签名与团队标识、配置文件权限详情、配对与信任记录），但**判定的瞬间不可回看**——iOS 不保存渲染快照，没有"当时显示了哪段文字"的可调取记录，因此既不能自证也不能事后归因（这条要和 #62 的可采性讨论放在一起读）。本篇因此也是全系列**唯一一处把主要防线放在动作之前**的层：事前核验成本极低、事后补救成本极高，处置重心不是提高警惕而是**把判定依据从名字挪到对象**，判定式一句话——"我此刻看到的名字，和系统将要执行的那个对象，是同一个东西吗？如果不是，我怎么在按下之前当场确认？"
