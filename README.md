前七篇是同一句话的七个部分：**输入到达的方式（网页、内容字节、接口调用、有线插入、卷挂载、线上报文）决定谁来解析它，解析所在的层决定缺陷的后果起点，而后果起点决定这件事是"厂商修"还是"你能关"。** 其中只有 #123 是远程触发的：它不需要你碰任何东西，也不需要介质靠近，所以它的"关不掉"权重比其余各篇更高一档。

第八篇往下再切一层，问的不是"谁来解析"，而是"**解析出来的东西由谁能解密**"。#118 讲文件里的字节、#122 讲卷结构的字节、#123 讲线上的字节，而 #124 讲保护这些字节的那把钥匙：算法没有被攻破，数据照样可读——因为缺陷藏在用法（只加密不认证、nonce 重用、随机源、该验没验）与生命周期（密钥落在哪个容器、派生强度、撤销与销毁）里，而不是藏在数学里。这一篇也是前八篇里唯一一类**个人杠杆真的生效**的：多数组件缺陷只能等更新，而密钥归属由用户与组织自己决定。它同样是唯一**向过去生效**的风险——今天泄露的钥匙打开昨天的数据，所以其余各篇的时间窗口模型在这里要反过来用。

第九篇再换一根轴：前八篇问的都是"一段字节进来，谁来解析它"，#125 问的是"设备知道自己在哪里、在做什么，这件事是从哪些层攒起来的"。定位与传感器没有"恶意文件"那样的入口，它的缺陷不在解析器里，而在**契约**里：来源即位置（信号本身没有身份）、授权即语义（关掉一个 App 的定位权限，运动与环境传感器仍按另一套口径被使用）、新鲜度假设、名字与对象分离、融合不可归因（所以逐项撤销根本不成立）、指示器即完整可见、失败即信息（拒绝授权本身被当成一次回答）。这也是前九篇里**可观测性最弱**的一篇：你能核对"自己给了多少"，核对不了"上层把哪些来源融合成了什么结论"；而其中一部分定位发生在服务端，设备上不留下任何可供审计的痕迹。个人杠杆在这里是部分的：服务级开关真的有效，融合层与原始传感器关不掉。它还给后果表添了一格前八篇没有的：**判定污染**——被污染的定位不只泄露你的行踪，还会写进考勤、门禁与理赔这些第三方记录里，而那里的损失不由设备厂商赔。

第十篇把方向倒过来：前九篇（除了 #124）处理的都是**输入**——外部字节或外部信号到达时，系统替你解析了什么、测量了什么；#126 处理的是**输出**——外部信号到达时，系统允许它**替你按下什么**。这一族的入口不是文件也不是报文，而是一组看起来无害的无障碍开关，以及三条没有身份概念的触发通路：声音（语音控制的自定义命令是一段可被**任何到达音频**触发的预置动作串，判定项里没有"说话的是谁"）、动作（摄像头与后置麦克风可以被当成开关输入）、连接（配对记录代表"这台设备被信任过"，不代表"此刻操作的是这个人"）。它的四个结构性结论是：**一次授予、全域生效**（界面措辞是"打开一个功能"，实际给的是一项覆盖任意前台内容的读取与操作能力，包括其他 App 显示的验证码）；**恢复即同意**（迁移与备份恢复把开关与已信任外设带回设备，其间没有任何一次重新征询——与 #107 的撤销不对称同族，但方向相反，是没打开过却已经是开的）；**锁屏不是输入隔离状态**（锁屏保护的是数据访问，不保证输入通路不可达）；以及本篇最重要的那条——**这是全系列唯一一个不提权的接管**：所有动作都发生在用户自己的会话、自己的权限、真实的界面里，所以服务端记录与本人操作不可区分，#91 的 C3 那一行"攻击者获得更高控制权"在这里要加注"权限等级未变"，归因只能靠形状与时间，不能靠记录本身。它还纠正一个从 Android 搬过来的直觉：iOS 上**没有第三方 App 可注册为辅助功能提供方**，所以"无障碍服务被监控软件滥用"这条路径在 iOS 上没有等价物——本族的风险面在系统功能 + 外部输入源 + 配置通道三者之间，"先查有没有可疑 App"这个第一反应在这里基本无效。可观测性与 #125 同档：开关当前态可见，变更的时间、来源与"这次操作是否来自合成事件"不可见，因此本篇不提供"如何发现自己被外部操作"的判定式，只提供十分钟清点 + 收窄触发源 + 记录基线三件事。
